# Classroom Walkthroughs

Build the selected examples with `make build` or use `make container-smoke`
for the reproducible environment. The commands below assume the repository
root is the working directory and that the image has already been built.

## Program text and data representation

```bash
build/bin/intro-hello
build/bin/show-bytes
```

Use `show-bytes.c` to connect integer, floating-point, pointer, and string
representations to the bytes printed by the program. The program's verbose
output is intentional for live discussion.

## Machine-level code and performance

```bash
less build/asm/120-branch.s
objdump -d build/bin/branch
readelf -S build/bin/branch
```

The assembly and disassembly are generated by the build; do not commit them.
`examples/opt/vec.c` is compiled as an object with `data_t=long` so students
can inspect vector layout and compiler output without introducing a custom
implementation.

## Linking and loading

```bash
build/bin/addvec
(cd build/bin && ./dll)
build/bin/interpose-linktime
build/bin/interpose-compiletime
```

Use `addvec` for ordinary object-file linking, `dll` for `dlopen`/`dlsym`, and
the two interposition binaries for link-time and compile-time replacement.
The shared library must be run from `build/bin` because the textbook example
uses `./libvector.so`.

The upstream runtime `LD_PRELOAD` variant is retained as source reference but
is not built: printing with `printf` from inside a `malloc` wrapper recurses
on modern glibc. The link-time and compile-time variants demonstrate the same
interposition concept without that runtime-specific failure.

## Exceptional control flow

```bash
build/bin/fork
build/bin/waitpid1
```

Use `sigsuspend`, `sigintsafe`, and `shellex` interactively when the lecture
has established signal handling. They are built by `make build` but are not
run by `make smoke` because they wait for signals or user input.

## Virtual memory

```bash
readelf -S build/obj/mm.o
nm build/obj/mm.o
nm build/obj/memlib.o
```

The allocator sources are included for source and object inspection. They are
not a standalone allocator lab and therefore have no automated executable
target here.

## System-level I/O

```bash
printf 'alpha\nbeta\n' | build/bin/cpstdin
printf 'line one\nline two\n' | build/bin/cpfile
```

Contrast one-byte Unix I/O with buffered Rio line input. Both programs are
safe to repeat and are included in the smoke suite.

## Network programming

```bash
build/bin/hostinfo localhost
```

For the echo pair, use two terminals in the same container or host:

```bash
build/bin/echoserveri 18080
printf 'hello\n' | build/bin/echoclient 127.0.0.1 18080
```

Stop the server with `Ctrl-C` after the exchange. Network execution is
documented but deliberately excluded from the non-interactive smoke suite.

## Concurrent programming

```bash
build/bin/hello
build/bin/badcnt 100000
build/bin/psum-local 2 8
build/bin/psum-mutex 2 8
```

`badcnt` is intentionally racy; its result and even whether the race is
visible can vary by run. Compare it with the mutex and local-accumulation
versions rather than treating one output as a test oracle.
